\subsection*{Response 1B -- Why the forecasting rule must depend on context}

\begin{figure}[H]\centering
\includegraphics[width=0.92\linewidth]{{figures/1.2-1}.pdf}
\caption{Output 1.2 -- Station 1 under Product A ($P\approx16.1$) and Product C ($P\approx30.1$).}
\label{fig:out12}
\end{figure}

The single matrix $\widehat W$ in Eq.~(8) is one fixed formula, fitted once on all training windows. These windows contain waves of very different speeds, with periods anywhere from 14 to 36 samples. A fast wave (16 samples) and a slow wave (30 samples) need to be continued differently over the next 48 steps. So, one formula can't fit both and ends up giving an average of the two.

This averaging is visible in Figure~\ref{fig:out12}. For Product~A, the shared and sensor-specific ridge forecasts have flattened peaks and start falling behind the true wave in the second half of the horizon (window RMSE 0.779 and 0.787).

Period-routed ridge uses a formula fitted only on waves of a similar speed, so it follows the true wave closely (0.232). When two waves that are out of step are averaged, they partly cancel each other out. That is why the shared forecast becomes weaker (smaller peaks), not just shifted in time.

\begin{figure}[H]\centering
\includegraphics[width=\linewidth]{{figures/1.3-1}.pdf}
\caption{Output 1.3 -- Attention maps for two Station 1 contexts and their difference.}
\label{fig:out13}
\end{figure}

Attention uses the same learned weights ($W_Q, W_K, W_V$) for every window. However, it computes its attention scores ($QK^\top/\sqrt{d_h}$) from the current window, so each new input produces a new set of weights.

Figure~\ref{fig:out13} shows this: the Product~A and Product~C maps focus on different positions (mean absolute weight difference 0.013, maximum 0.284). So, attention mixes each window in its own way, whereas ridge applies the same $\widehat W$ to every window. This only shows that attention adapts to the input. It doesn't prove that attention has found the actual period of the wave.

\subsection*{Response 2 -- Separating slow structure from repetition}

\paragraph{Choosing the width $m$.}

\begin{figure}[H]\centering

As $m$ grows, the trend becomes a smooth ramp and the remainder becomes a clean, full-size wave (std 1.572 at $m=41$). In numbers, oracle period recovery rises from 0.687 (raw) to 0.998 ($m=41$). So, we selected $\mathbf{m=41}$. Note that the choice depends on what we measure: $m=41$ gives the best recovery within one sample, while $m=25$ gives the smallest median period error.

\paragraph{Why a moving average suits this world.}
The drift changes slowly, over about 240 samples, while the vibration repeats every 14--36 samples. A 41-sample window is longer than every vibration cycle, so it averages each cycle out to about zero. Yet it is much shorter than 240, so the drift passes into the trend almost unchanged. The oracle check is a fair way to pick $m$ because it tests exactly what we want: does the remainder show the true repeating pattern? It uses training data only, so validation and test data stay untouched.

\paragraph{Where it fails, and an alternative.}
A fixed moving average struggles with a sudden jump in level, e.g.\ a product changeover or an impact inside the window. It spreads the jump over 41 samples and leaks a false bump into the remainder. It would also fail if a vibration cycle were longer than the window. An alternative is STL/LOESS decomposition, which fits small local curves instead of a flat local average. It handles a curved trend better, but needs more computation and tuning.

\subsection*{Response 3 -- Mixing by temporal delay}

\texttt{aggregate\_delays} gives the same answer as the worked example (35, 15, 25, 25). So $z_0 = 35$, and the shift runs in the right direction. It also passes the gradient check. Output 3.1 confirms that \texttt{delay\_scores} matches a direct circular correlation (4, $-4$, 4, $-4$).

\begin{figure}[H]\centering
\includegraphics[width=\linewidth]{{figures/3.2-1}.pdf}
\caption{Output 3.2 -- signal-level recurrence diagnostic (Station 2, Product A, $P\approx16.1$). This is a correlation computed directly from the signal, not the model's learned q/k scores.}
\label{fig:out32}
\end{figure}

\paragraph{Strongest lags.} After removing the trend, the correlation peaks at lag 16 (0.896) and lag 32 (0.897). These match the wave's period ($P\approx16.1$) and twice the period ($\approx32.3$). The dips at about 8, 24 and 40 are half a period apart, where the peaks of one copy line up with the troughs of the other.

\paragraph{Why decomposition helps.} In the raw signal, the correlation just keeps dropping, from about 0.45 at lag 8 to $-0.55$ at lag 40, with no peak at the period. The slow ramp looks similar to itself at every small shift, so it hides the repeating wave. Once the trend is removed, an almost pure wave is left, and peaks appear only at multiples of the period. This is exactly what the delay mixer relies on.

If the useful information sits at a few repeating gaps, it makes sense to score $L$ delays instead of all $L^2$ position pairs, and to combine shifted copies of the signal. This works best on the decomposed signal. In line with this, the delay mixer alone already halves Raw Attention's error in Output 4.1 (0.436 $\to$ 0.214).

\paragraph{Where delay mixing goes wrong.} A one-off event, like a single knock from a loose part, never repeats. The delay mixer can only reuse shifted copies of the window, so it would either average the event away or copy it forward as false ``echoes''. Similarly, if the speed changes quickly within one window (e.g.\ while the machine is speeding up), no small fixed set of delays fits the whole window.

\section*{Task 2 -- Leaderboard Challenge (Autoformer)}
\addcontentsline{toc}{section}{Task 2}

We created three versions of the model, one for each leaderboard submission, and improved each one based on our validation results. The final model is a small Autoformer with 23{,}362 parameters. On top of the standard Autoformer, it has two additions:
\begin{itemize}
  \item a \textbf{non-linear covariate head}, which lets the external data affect each forecast step directly;
  \item a \textbf{floor layer}, which stops the forecast from going below a realistic minimum value (14.7).
\end{itemize}

\subsection*{Data exploration and periodic structure}

\begin{figure}[H]\centering
\includegraphics[width=0.95\linewidth]{figures/t2-series.pdf}
\caption{Task 2 history with the early-stop (orange) and evaluation (red) regions; the dotted line is the forecast floor (14.7).}
\label{fig:t2series}
\end{figure}

\paragraph{Heavy tails.} The values range from 0 to 994 and can jump by ten times within a few days. Exact zeros almost never occur (only 2 of 43{,}656 hours).

\begin{figure}[H]\centering
\includegraphics[width=\linewidth]{figures/t2-periodicity.pdf}
\caption{Periodogram, autocorrelation and mean by 24-step phase.}
\label{fig:t2period}
\end{figure}

\paragraph{Repeating cycles.} The periodogram peaks at 24 steps and near 8{,}730 (close to 8{,}766, the number of hours in a year). So, the data is most likely hourly, with a daily and a yearly cycle. The daily cycle is weak: the average value across the day only moves between 86 and 113, around an overall mean of 98. Since no dates are given, we turned these two cycles into sin/cos ``phase'' features, which replace the time stamps Autoformer normally uses.

\paragraph{Short memory.} The autocorrelation is 0.97 one hour apart but drops to 0.40 after a day, 0.16 after two days and 0.03 after a week. So, the recent past says very little about most of the 168-hour forecast.

\paragraph{External file.} It has six continuous features (A--F) and four on/off flags (G--J), where only one flag is on at a time. On their own, they are only weakly related to the target (strongest: D $-0.25$, H $-0.21$, A $+0.17$, J $+0.15$). So, whether they actually help had to be tested by experiment. To prepare them, we applied \texttt{log1p} to the very skewed features D--F, standardised the continuous features using the training data, and kept the flags as 0/1.

\subsection*{Validation protocol}

\paragraph{Split.} The data was split in time order. Training used steps 1--37{,}608, the next 12 weeks were used only for early stopping, and the final 24 weeks were kept for evaluation.

\paragraph{Scoring.} Each of the 24 evaluation weeks was scored separately using MAE, RMSE and sMAPE, and the scores were then averaged. Weeks 12--23 are the most recent and most volatile, so they were treated as the closest match to the leaderboard week.

\paragraph{Seeds.} Every configuration was run with 3 random seeds and reported as mean $\pm$ std. Configurations were also compared week by week to confirm that any difference was genuine.

\subsection*{Model design}

\begin{itemize}
  \item \textbf{Autoformer body.} The Auto-Correlation and series-decomposition layers are adapted from the official implementation (\href{https://github.com/thuml/Autoformer}{github.com/thuml/Autoformer}, MIT licence; Wu et al., 2021) and wired as in its reference model: input decomposition (moving average, kernel 25); a decoder trend initialised from the window mean and a seasonal part from zeros; Auto-Correlation in the encoder and in both decoder attentions, keeping $k=\lfloor \ln L\rfloor = 5$ delays; decomposition after every attention and feed-forward block, with the trend accumulated through the decoder. The adapted files are in \texttt{Task 2 - Leaderboard/autoformer/}, with the source credited in each file header.
  \item \textbf{Size:} $d_{\text{model}}=32$, 4 heads, 1 encoder and 1 decoder layer, $d_{ff}=64$. Input length 168, label length 48, \texttt{pred\_len} 168.
  \item \textbf{Embedding (my own):} a circular-conv value embedding plus a linear map of the marks (phase features + covariates), with no positional encoding. The encoder and decoder take separate marks, which is what the external-data ablation varies.
  \item \textbf{Exogenous head:} a term added at each forecast step, computed from the decoder marks over the horizon. Auto-Correlation aggregates time-shifted copies of the whole sequence, which blurs an effect tied to one step, and the head keeps that effect local. It is a 5-step convolution, a GELU and a 1$\times$1 convolution (1{,}153 parameters), so it reacts to \emph{changes} in the covariates, not only their levels.
  \item \textbf{Floor layer:} the last operation is $\max(\hat y, f)$ with $f=14.7$, the 10th percentile of the training target.
  \item \textbf{Training:} MSE on the standardised target; AdamW (weight decay $10^{-4}$, learning rate $3\times10^{-4}$, $3\times10^{-3}$ for the head); cosine schedule; dropout 0.25; batch 64; training windows every 2 steps; early stopping with patience 4 (maximum 15 epochs).
\end{itemize}
Per model: \textbf{23{,}362} trainable parameters (22{,}209 body and embeddings + 1{,}153 head).

\begin{itemize}
  \item \textbf{First version.} It used a linear covariate head, a single seed and no refit, with negative values clipped at 0. It scored 93.8 on the leaderboard, against a validation mean of 60.5. The calm early weeks had made the average look better than it was. On the recent weeks alone, the same model scored 79.3, with weekly RMSE ranging from 33 to 101. So, from then on, models were selected on weeks 12--23 only.
  \item \textbf{Second version.} Three changes were made here:
  \begin{itemize}
    \item Regularisation was tried first but did not help ($+0.67 \pm 1.36$, better on only 6 of 24 weeks). Every run still peaked at epoch 1 or 2, so the early stopping was not caused by overfitting.
    \item The linear head was replaced with a non-linear one. This lowered RMSE by $3.05 \pm 4.41$ and was better on 17 of 24 weeks, since the largest errors happen at sudden changes, which a 5-step convolution can capture.
    \item The models were retrained on the full history, which improved every seed ($-0.53$ RMSE), and three seeds were averaged, which lowered RMSE by a further 1.5--2.5. Clipping at 0 was also replaced with a floor of 14.7, applied after prediction.
  \end{itemize}
  It scored 71.48 on the leaderboard (8th).
  \item \textbf{Third version.} The only change was moving the floor inside the model as a layer, so the model learns with it during training. Compared with the second version, this lowered RMSE by $1.08 \pm 2.63$, and by more on the seed-averaged recent weeks (71.40 $\to$ 68.34, with MAE falling from 45.7 to 42.0). It scored 67.22 on the leaderboard (3rd).
\end{itemize}

% ---------------------------------------------------------------------
\subsection*{The forecast floor}

A forecast floor is simply the lowest value the model is allowed to predict. The target here is never negative and almost never zero, so a forecast below a realistic minimum can only be wrong. In the first version, negative outputs were clipped at 0, which gave long runs of exact zeros at the end of the forecast. On validation weeks where this happened, the true values averaged around 14, not 0. So, in the second version, the floor was raised to 14.7, the 10th percentile of the training data, and applied after prediction.

In the third version, the same floor was moved inside the model as a layer, so the model trained with it rather than having its output trimmed afterwards. This improved the score, but the forecast now sits exactly at 14.70 for 44 of 168 hours, at the start and end. In these hours the external data points to a low period, and the model pushes its output well below the floor.

A natural next step would be to let the model learn the floor, either by learning the floor level itself during training or by using a smooth floor that still passes a learning signal below 14.7. This would let it predict values such as 18 or 25 in low periods instead of a flat 14.70. However, since the third version already scored well and matched its validation estimate, and the expected gain was small, this was left untested.
